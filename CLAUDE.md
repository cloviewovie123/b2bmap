# Bin to Better – Project Brief

Bin to Better is a nonprofit that collects used tennis balls for recycling/reuse.
This project has two parts:

1. **Interactive map** – a Leaflet + OpenStreetMap web page showing every
   collection (pickup) site and dropoff site, with marker size based on balls collected.
2. **Route optimizer** – a Python script using Google OR-Tools that compares
   our current pickup route to the optimal one.

The site will be hosted on **GitHub Pages** (static files only: HTML/CSS/JS/JSON, no server).

## About the user

- **Ask before deleting or overwriting anything.** This includes files, folders, and
  anything in `data/raw/`. Never run destructive git commands without asking.
- `NOTES.md` is the user's own notebook. Do not edit it unless asked.

## Data
- `data/raw/` – original CSVs. **Treat as read-only; never modify.**
  - `Bounce Back Resource Sheet - Past Pickups (1).csv` – columns: Name, Center, Ball Count, Contact #, Notes, Date
  - `Bounce Back Resource Sheet - Past Dropoffs.csv` – columns: Name, Dropoff location, Ball Count, Contact #, Notes, Date
- `data/clean/` – cleaned output (e.g., with coordinates). Generated by scripts from raw data.
  Ask before overwriting existing files here.

### Data decisions (made by the user)
- **Geocoding**: Claude finds addresses/coordinates on its own and saves them in `data/clean/`. Flag any low-confidence match.
- **Name variants** (e.g. "Allie's Doggy Daycamp" / "Allie's Doggie Day Camp"): merge them without asking; list what was merged.
- **Date 9/20/2026 (Love Second Chances) is correct**, not a typo. Leave it.
- **Personal contact info**: remove the Contact # column from everything in `data/clean/` and the web page. `data/raw/` stays untouched (ask before editing it).
- Dates are M/D/YYYY. "Name" is the volunteer(s). Sites repeat, so total balls per site and keep per-visit history in the popup.

## Map requirements
- Leaflet with OpenStreetMap tiles (include the required attribution).
- Pickups and dropoffs visually distinct (different colors) with a legend and a layer toggle.
- Marker size scales with total balls (scale by area, e.g. sqrt, so one huge site doesn't swamp the rest).
- Popup: site name, type, total balls, number of visits, last visit date.
- Plain JavaScript, loading a JSON/GeoJSON file. No build step, so it works on GitHub Pages as-is.
- Leaflet loaded from a CDN with a pinned version.

## Route optimizer
- `scripts/optimize_route.py`: Python + OR-Tools. Default compares nearest-first (the usual method) with the optimum for all pickup sites and writes `docs/data/routes.json`.
  `--stops "Site A,Site B"` compares the user's own list (any pickup or dropoff sites) and prints the result.
- `scripts/build_matrix.py`: measures real driving time/distance between every pair of places (Fremont + all sites) with OSRM and writes `docs/data/matrix.json`. Rerun when `sites.json` changes.
- **Web route planner (Plan tab)**: the user clicks sites (popup "Add to route" or "+" in the Sites tab) to build their own route, because not every site says yes on the same day.
  GitHub Pages can't run Python, so the page solves the route in JavaScript from `matrix.json`: Held-Karp (exact) up to 15 stops, 2-opt beyond that.
  It compares **My order** (as clicked) vs **Nearest-first** vs **Best**, and draws real road shapes fetched from OSRM.
  The JS result was checked against OR-Tools and matches.
- Depot: Fremont, CA. One driver, one vehicle, no capacity or time-window limits.
- "Current route" = nearest-neighbor: closest stop to Fremont first, then repeatedly the closest unvisited stop, then home.

## Keeping the README and GitHub description current
- The stats table in `README.md` (between `STATS:START` and `STATS:END`) is generated by
  `scripts/update_readme.py` from `docs/data/sites.json` and `docs/data/routes.json`. Never edit it by hand.
- **Whenever the data changes** (after rerunning `clean_data.py`, `build_matrix.py`, or `optimize_route.py`),
  run `python scripts/update_readme.py --github` before committing. This refreshes the README stats and
  updates the repo's GitHub description with `gh repo edit`.
- If `gh` isn't installed or logged in, run it without `--github` and tell the user to run `gh auth login`.
- Include the updated `README.md` in the same commit as the data change.
