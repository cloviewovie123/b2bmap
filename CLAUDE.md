# Bin to Better – Project Brief

Bin to Better is a nonprofit that collects used tennis balls for recycling/reuse.
This project has two parts:

1. **Interactive map** – a Leaflet + OpenStreetMap web page showing every
   collection (pickup) site and dropoff site, with marker size based on balls collected.
2. **Route optimizer** – a Python script using Google OR-Tools that compares
   our current pickup route to the optimal one.

The site will be hosted on **GitHub Pages** (static files only: HTML/CSS/JS/JSON, no server).

## Data
- `data/raw/` – original CSVs. **Treat as read-only; never modify.**
  - `Bounce Back Resource Sheet - Past Pickups (1).csv` – columns: Name, Center, Ball Count, Contact #, Notes, Date
  - `Bounce Back Resource Sheet - Past Dropoffs.csv` – columns: Name, Dropoff location, Ball Count, Contact #, Notes, Date
- `data/clean/` – cleaned output (e.g., with coordinates). Generated by scripts from raw data.
  Ask before overwriting existing files here.

- Dates are M/D/YYYY. "Name" is the volunteer(s). Sites repeat, so total balls per site and keep per-visit history in the popup.

## Map requirements
- Leaflet with OpenStreetMap tiles (include the required attribution).
- Pickups and dropoffs visually distinct (different colors) with a legend and a layer toggle.
- Marker size scales with total balls (scale by area, e.g. sqrt, so one huge site doesn't swamp the rest).
- Popup: site name, type, total balls, number of visits, last visit date.
- Plain JavaScript, loading a JSON/GeoJSON file. No build step, so it works on GitHub Pages as-is.
- Leaflet loaded from a CDN with a pinned version.

## Route optimizer requirements
- Python with `ortools` (install in a virtual environment; explain what that is).
- Model as a routing problem (TSP / vehicle routing) over the pickup sites, starting and ending at a depot.
- Use real driving distances/times (e.g., OSRM or similar) rather than straight-line if feasible;
  explain the tradeoff. Cache results so we don't re-request.
- Compare **current route vs. optimal route**: total distance/time and % saved.
- Output route data the map can display (e.g., JSON) and a short plain-language summary.
- **Depot**: Fremont, CA. Every trip starts and ends there. One driver, one vehicle, no capacity or time-window limits.
- **"Current route"** = nearest-neighbor: go to the pickup site closest to Fremont, then repeatedly to the closest unvisited site, then return to Fremont. Implement this greedy baseline and compare it to the OR-Tools optimum.
- Pickup sites only (dropoffs are not part of the route) unless the user says otherwise.
